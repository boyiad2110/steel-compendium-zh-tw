## 範圍與版本

- 目標：每個批次有可追溯 PR，先引導本地人工驗收，通過後再收尾合併至 `develop`。
- 使用者指示：2026-10-22 要求「之後每個批次都請開 PR，然後引導我進行本地人工驗收，驗收完再收尾合併」。
- 包含：Agent 規則、文件入口、開發與工作流程、批次範本、PR 範本及本批紀錄。
- 不包含：網站內容／程式、Master、快照、分支保護、CI 行為、部署與 B01 實作。
- 基準 commit：`6be639c62`；工作分支：`codex/gov-02-batch-pr-workflow`；目標：`develop`。
- PR：建立後補上；驗收版本以該 PR 最新提交為準。

## 本地人工驗收步驟

本批只修改文件，直接檢閱本地工作分支，不需啟動網站。

1. 在 [workflow.md](../workflow.md) 查看「一批的工作流程」：每批開 Draft PR，先提供本地驗收步驟，未通過前不合併。
2. 查看同檔「狀態及驗收證據」：驗收對應 PR commit；修正留在原 PR，內容變動需重驗，補驗收紀錄不需重新審同一內容。
3. 在 [development.md](../development.md) 查看「分支與整合」：每批用獨立 `codex/` 分支，透過 PR 合併 `develop`。
4. 查看 [批次範本](_template.md) 及 [PR 範本](../../.github/pull_request_template.md)，確認都有版本、驗收與收尾紀錄。
5. 確認驗收通過後由 Agent 補紀錄、等待最新檢查通過並合併；部署仍需另外指示。

網站、搜尋、匯出及深淺色畫面測試不適用，沒有網站變更。

## 驗證

- 提交前檢查現行文件本地連結、差異空白、僅 Markdown 變更與舊規則殘留，結果於 PR 摘要記錄。
- 本地程式測試及全站建置未執行：純文件變更；GitHub PR 仍依既有工作流程執行檢查。
