## 本地人工驗收

本批是 CI 工程，沒有網站畫面變動，不需啟動網站。請在 repo 根目錄的 PowerShell 執行：

```powershell
.venv\Scripts\python.exe scripts/ci/check.py classify --files README.md .repo-docs/batches/CI-01.md
.venv\Scripts\python.exe scripts/ci/check.py classify --files README.md docs/index.md
.venv\Scripts\python.exe scripts/ci/check.py classify --event workflow_dispatch --files README.md
.venv\Scripts\python.exe scripts/ci/check.py docs --base origin/develop
.venv\Scripts\python.exe -m unittest discover -s tests -p test_ci.py -v
```

預期依序為 `docs`、`full`、`full`；文件檢查 `errors` 為空；測試皆通過。錯誤案例會在測試中驗證，不需要手動破壞真實文件。

檢閱 [development.md](../development.md) 的「CI 的實際行為」及 [工作流程 YAML](../../.github/workflows/zh-tw.yml)，確認：

1. 同一 PR 更新後取消舊檢查，手動部署不取消前次執行。
2. 純文件路徑省略網站依賴、Node、網站測試與建置，但保留分類／文件測試及固定 `check`。
3. 任意非白名單檔案及所有手動執行仍走完整驗證；pip 快取只減少下載。
4. 本 PR 修改 CI 本身，因此遠端 Summary 應為 `full`，完整驗證須成功且 `deploy` 跳過。

此批不額外開純文件測試 PR；快速分類與失敗案例由本地／CI 測試及既有 PR #1 的真實檔案清單重播驗證。真正純文件 PR 的遠端耗時需在後續批次量測，不預先宣稱已節省多少秒。
