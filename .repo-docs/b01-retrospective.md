# B01 人類中文化檢討與後續族裔改進

日期：2026-10-23。依據：[B01 紀錄](batches/B01.md)、[PR #3](https://github.com/boyiad2110/steel-compendium-zh-tw/pull/3) 及[收尾留言](https://github.com/boyiad2110/steel-compendium-zh-tw/pull/3#issuecomment-6345643520)。本報告由 [GOV-03](batches/GOV-03.md) 提出；現行規則仍由索引列示的各主題文件負責。

## 結論與證據界線

B01 最終完成創角規則、介紹與「談人類」故事，使用者於 2026-10-23 明確驗收通過；合併版本為 `8bf48e5486906dc9e2469e1f46819d728c71a031`，未部署。最終本地完整驗證記錄為 Python 30 項、JavaScript 124 項、3,580 頁建置及產物檢查通過；[最新 PR CI](https://github.com/boyiad2110/steel-compendium-zh-tw/actions/runs/39812233047) 成功。

結果達成，但交付前的語境盤點、畫面檢查及預覽管理不足，增加使用者找問題與重驗的負擔。這些是執行者應改善的地方。原定排除敘事符合當時授權；後續追加也有取得指示，問題在於沒有提早把「可完成創角」與「整頁中文化」的差別具體列給使用者。

本報告不把使用者最終通過回填成所有 Agent 檢查都曾執行。舊紀錄中尚未執行的手機／深色／匯出等項目，仍依其當時證據理解；沒有工時或重工成本的完整數據，不推估節省比例。

## 做得不好的地方及改善

| 問題與實例 | 成因與影響 | 後續做法／負責時點 | 可檢查的結果 |

| Distance 一度準備套用「射程」，需使用者指出是強制移動距離；介紹 supernatural 亦與規則詞不同 | 以全站術語取代上下文判斷，讓正確段落回退或產生錯誤建議 | 翻譯盤點先看整句、規則／敘事用途及連結目的地；把同字不同義的差異一起列出，再確認必要調整 | 個案標明語境與適用紀錄；不把「距離」「超自然」全站取代其他核准詞 |

## 做得好的地方及保留方式

| 有效做法與證據 | 後續保留方式 |
|---|---|
| 網站只讀核准快照；缺 UI、成本及故事新譯先取得使用者確認 | 沿用核准來源、版本與紀錄 ID；標點／連結適配也不能成為自行核准的捷徑 |
| 「談人類」基本檢查提出兩處文字修正與標題，由使用者一併同意後保留其餘定稿 | 將必要問題與建議集中送審，尊重定稿，不擅自潤飾；已有明確答案不再問 |
| 兩份 Master 新故事逐格讀回，擷取前後修改時間一致，舊核准投影未變，快照只新增 18 筆 | 寫入後確認內容、狀態、格式與來源；只在明確授權下同步 Book 與 SC，不能把 B01 雙寫當成每批預設 |
| 中文化集中顯示接點，保留生成文件、機器資料與連結目的地 | 沿用共用顯示機制；新族裔遇到未涵蓋結構才增加有界適配，不複製整頁或堆全站詞彙替換 |
| 標題結構、主頁自連結與語境適配有回歸案例；主頁及章節的故事逐字核對 | 後續實作延用代表案例，另外核對新族裔的特殊結構；同時驗證不應命中的內容仍回退 |
| 同一 PR 修正、部分驗收保留、最後完整範圍明確通過；最新 CI 成功才合併 | 修正清單對應受影響頁與版本，避免要求使用者重驗無關項目；工程／譯文／人工驗收持續分開 |
| 使用者提供英文原站 PNG 對照，確認裁切屬上游既有問題 | 匯出問題以同內容／操作條件比較中英文，保留限制與處置，不任意歸咎翻譯，也不為上游缺陷擴大批次 |

## 下一個族裔的實際工作順序

1. **盤點**：依[批次範本](batches/_template.md)列規則、介紹、故事、UI 與直接引用；標明包含或排除。從實際頁面反查 Master，筆數只作線索。
2. **整理待審**：一次列出缺譯、原文實質差異、排版差異、語境與候選衝突；先採已吻合的核准定稿，讓使用者只判斷必要差異。
3. **接線及自查**：共用既有機制，檢查每個適用呈現位置；先做針對性診斷，再依 development 完整驗證。不得因只改最後一筆文件就略過整個內容 PR 的完整 CI。
4. **交付**：統一預覽並核對服務版本；提供精確網址、操作、預期結果及英文原因。執行者先完成適用檢查，再請使用者做內容與使用體驗的人工驗收。
5. **修正與收尾**：每次只重驗新增與受影響範圍；取得明確通過後依 workflow 合併。結果與限制留在當前摘要，詳細過程放歷史紀錄。
